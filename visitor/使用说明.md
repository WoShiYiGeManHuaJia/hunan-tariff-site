# 自己搭一套「资费变化定时推送」

不影响原站任何配置。本方案**只读公开数据**，你自己的 Webhook、自己的时间、自己的仓库。

## 三步搞定

### 1. 建仓库
GitHub 新建一个空仓库（公开或私有都行，私有也够用：Linux runner 免费额度每月 2000 分钟）。

### 2. 放两个文件
| 文件 | 放哪 |
|---|---|
| `visitor_summary.py` | `scripts/visitor_summary.py` |
| `visitor-notify.yml` | `.github/workflows/visitor-notify.yml` |

### 3. 填你自己的推送渠道
进仓库 → **Settings → Secrets and variables → Actions → Secrets** → New repository secret：

| 名称 | 说明 |
|---|---|
| `DINGTALK_WEBHOOK` | 钉钉机器人 Webhook（`https://oapi.dingtalk.com/robot/send?access_token=...`） |
| `DINGTALK_SECRET` | 机器人安全设置选了「加签」才填，SEC 开头 |
| `DINGTALK_KEYWORD` | 安全设置选了「关键词」才填，比如「资费」 |
| `FEISHU_WEBHOOK` / `FEISHU_SECRET` | 飞书，同上 |
| `WECOM_WEBHOOK` | 企业微信群机器人 Webhook |
| `SMTP_HOST/PORT/USER/PASS`、`MAIL_TO` | 邮箱（端口 465 用 SSL，587 用 STARTTLS） |

填完去 **Actions** 页手动点一次 `资费变化定时推送` → Run workflow，验证能不能收到。

## 可选：只推你关心的

在 **Settings → Variables** 里加：

- `PUSH_OPS` = `mobile,unicom` → 只推移动和联通（电信广电不再出现）
- `PUSH_PROVS` = `quanguo,hunan,guangdong` → 只统计这些省份，并在推送里列出分省明细
- `SINCE_HOURS` = `24` → 统计窗口

不填就是全部，行为跟默认一致。

## 改推送时间

编辑 `.github/workflows/visitor-notify.yml` 里的 cron，**UTC 时间**：

```
北京 08:00 → cron: "0 0 * * *"
北京 20:00 → cron: "0 12 * * *"
北京 09:30 → cron: "30 1 * * *"   （UTC = 北京 - 8 小时）
```

⚠️ GitHub 免费账号的定时任务**可能被平台延后几十分钟到几小时**，这是平台行为，改 cron 解决不了。要精确到分钟，用 cron-job.org 之类外部定时去打 `repository_dispatch`。

## 常见问题

**收到 403 Forbidden**
机器人开了「加签」或「关键词」安全设置。把 `DINGTALK_SECRET` 或 `DINGTALK_KEYWORD` 补上。

**一直没收到**
先手动 Run workflow 看日志。日志里会打印「✗ 某某：原因」。

**企业微信 / 邮箱**
由本脚本直接发（跑在 GitHub 服务器上，不受浏览器跨域限制），填了 Secrets 就能用。

**能推几个账号**
一个仓库可以配多个渠道同时推；想给多个人推，让他们各自按本文建一个仓库即可。
